Introduction
In the realm of software development, setting up a new project with Docker Compose can be a repetitive and time-consuming task. Ensuring consistency across projects, initializing Git repositories, and integrating with GitHub are essential steps that often require manual intervention.

To streamline this process, I’ve developed a script-based solution that automates the initial setup of Docker Compose projects, including directory structure creation, Git repository initialisation and automatic commits and pushes to GitHub.

In this article, I’ll walk you through the implementation of these automation scripts, breaking down the code into digestible parts with detailed explanations.

Overview
The solution consists of two primary scripts:

generate_project.sh: Sets up the initial project structure, initializes a Git repository, and pushes the initial commit to GitHub.
commit_git.sh: Automates the process of committing and pushing subsequent changes.
Both scripts work together to provide a seamless workflow from project creation to ongoing development.

Setting Up the Project Structure: generate_project.sh
The generate_project.sh script is designed to automate the initial setup of a Docker Compose project. It creates necessary files and directories, initializes a Git repository, and configures a GitHub repository.

Script Breakdown:

#!/bin/bash

# Check if an input file and project name are provided
if [ -z "$1" ] || [ -z "$2" ]; then
  echo "Usage: $0 <input JSON file> <project name>"
  exit 1
fi

INPUT_FILE="$1"
PROJECT_NAME="$2"
The script starts by checking if the required arguments (<input JSON file> and <project name>) are provided. These inputs are essential for defining the project configuration and naming.

# Check if jq and gh are installed
if ! command -v jq &> /dev/null; then
    echo "jq is required to parse JSON. Please install jq."
    exit 1
fi

if ! command -v gh &> /dev/null; then
    echo "GitHub CLI (gh) is required to create repositories. Please install gh."
    exit 1
fi
The script ensures that jq (for parsing JSON) and gh (GitHub CLI for interacting with GitHub) are installed. If not, it prompts the user to install them.

# Verify the JSON file exists and is readable
if [ ! -f "$INPUT_FILE" ]; then
  echo "Error: The specified JSON file does not exist: $INPUT_FILE"
  exit 1
elif [ ! -r "$INPUT_FILE" ]; then
  echo "Error: The specified JSON file is not readable: $INPUT_FILE"
  exit 1
fi
It checks whether the specified JSON file exists and is readable. This file contains configurations like directory structure and files to include.

# Create the root project directory
mkdir -p "$PROJECT_NAME"
cd "$PROJECT_NAME" || exit
The script creates the root project directory using the provided project name and navigates into it.

# Extract the gitignore path from the JSON file
GITIGNORE_PATH=$(jq -r '.gitignore' "../$INPUT_FILE")

# Copy the gitignore file to the project directory, expanding the tilde to home directory
if [ -n "$GITIGNORE_PATH" ]; then
  if [[ "$GITIGNORE_PATH" == \~/* ]]; then
    GITIGNORE_PATH="${HOME}${GITIGNORE_PATH:1}"
  fi

  if [ -f "$GITIGNORE_PATH" ]; then
    cp "$GITIGNORE_PATH" .gitignore
  else
    echo "Provided gitignore path is invalid or the file does not exist. Creating a blank .gitignore."
    touch .gitignore
  fi
else
  echo "gitignore path is not specified in the JSON file. Creating a blank .gitignore."
  touch .gitignore
fi
The script extracts the .gitignore path from the JSON configuration and copies it to the project directory. If the file path is invalid, it creates a blank .gitignore.

# Create root-level files
touch docker-compose.yml .env README.md

# Create package.json file
echo '{
  "name": "'$PROJECT_NAME'",
  "version": "1.0.0",
  "description": "A Docker Compose setup for '$PROJECT_NAME'",
  "main": "index.js",
  "scripts": {
    "start": "docker-compose up",
    "stop": "docker-compose down"
  },
  "author": "Your Name",
  "license": "MIT",
  "dependencies": {}
}' > package.json
The script creates essential files such as docker-compose.yml, .env, and README.md. It also generates a package.json file, which is crucial for projects using Node.js. This file includes metadata about the project and common scripts for managing Docker Compose.

# Create shared directory and its contents
mkdir -p shared
jq -c '.shared[]' "../$INPUT_FILE" | while read shared_resource; do
  shared_resource=$(echo "$shared_resource" | jq -r '.')
  if [[ "$shared_resource" == */ ]]; then
    mkdir -p "shared/$shared_resource"
  else
    touch "shared/$shared_resource"
  fi
done
The script iterates through the shared resources specified in the JSON file, creating directories and files as necessary.

# Create application directories, config files, and initialization scripts
jq -c '.apps[]' "../$INPUT_FILE" | while read app; do
  app_name=$(echo "$app" | jq -r '.name')
  config_file=$(echo "$app" | jq -r '.config')
  init_script=$(echo "$app" | jq -r '.init')

  mkdir -p "$app_name/src"
  touch "$app_name/Dockerfile"
  touch "$app_name/$config_file"
  touch "$app_name/$init_script"
done
For each application defined in the JSON file, the script sets up a directory structure and initializes necessary files, such as Dockerfiles, configuration files, and initialization scripts.

# Copy the commit_git.sh script to the project directory
COMMIT_SCRIPT_PATH="/commit_git.sh"
if [ -f "$COMMIT_SCRIPT_PATH" ]; then
  cp "$COMMIT_SCRIPT_PATH" ./commit_git.sh
  echo "commit_git.sh script copied to the project directory."
else
  echo "commit_git.sh script not found at $COMMIT_SCRIPT_PATH."
fi
It copies the commit_git.sh script into the project directory. This script is crucial for automating commits and pushes.

# Initialize Git repository and make an initial commit
git init
git add .
git commit -m "Initial commit for $PROJECT_NAME"

# Create a new GitHub repository using gh CLI
gh repo create "$PROJECT_NAME" --public --source=. --remote=origin --push

# Rename the default branch to 'main' and push to the remote repository
git branch -m main
git push -u origin main
The script initializes a Git repository, makes the initial commit, creates a corresponding GitHub repository, renames the default branch to main, and pushes the changes.

Automating Commits and Pushes: commit_git.sh
The commit_git.sh script simplifies the process of committing and pushing changes to the GitHub repository.

Script Breakdown

#!/bin/bash

# Navigate to the project directory
cd ./ || exit
Ensures the script operates within the project directory.

# Ensure the SSH agent is running and the key is added
if ! pgrep -u "$USER" ssh-agent > /dev/null; then
    eval "$(ssh-agent -s)"
fi
ssh-add -l &>/dev/null || ssh-add ~/.ssh/id_ed25519
Checks if the SSH agent is running and if the SSH key is added, preventing repeated prompts for the SSH key passphrase.

# Get the current date
DD=$(date +'%d')
MM=$(date +'%m')
YYYY=$(date +'%Y')

# Define the commit message with the current date
COMMIT_MESSAGE="$DD/$MM/$YYYY - Updated configuration and fixed bugs"

# Check the status of your working directory
git status
Retrieves the current date and constructs a commit message that includes this date.

# Stage all changes, including new files
git add .

# Commit the changes with the dynamically generated message
git commit -m "$COMMIT_MESSAGE"

# Push changes to the 'main' branch on the remote repository
git push origin main
Stages all changes, commits them with the generated message, and pushes the changes to the main branch.
